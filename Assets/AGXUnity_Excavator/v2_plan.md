# 智能挖掘机项目 V2 工作说明与阶段目标

## 一、文档目的

本文档用于说明智能挖掘机项目在 V2 阶段的核心工作内容、推进顺序以及各阶段预期目标，供后续研发实施、组会汇报、任务拆解和成员协作时统一理解与对齐。

V2 阶段不是对 V1 的简单延伸，也不是继续围绕单次固定动作流程进行局部调参。V2 的任务，是在 V1 已经证明“单轮技能可学”的基础上，进一步推动系统从“能够完成一次固定流程”升级为“能够在变化环境中连续、多轮、相对平滑地执行作业任务”。V1 已经验证了当前 AGX testbed 的 live 交互、数据录制、离线训练和 live rollout 评测闭环均已打通，且当前固定下来的 `v1` 业务基线在 `dump_complete_final_hold` 口径下已经达到 `10/10 success`，因此当前工作的重点已经不再是“能不能学会一次任务”，而是“如何把单轮技能发展为可重复调用、可适应变化环境、并支持连续作业的系统能力”。 

---

## 二、V2 阶段要解决的核心问题

V2 阶段之所以必要，是因为当前系统虽然已经学会了单轮“挖土—转移—倾倒”的基本任务骨架，但距离更真实、更复杂、更连续的作业目标仍有明显差距。当前任务通常在一次倾倒完成后结束，这样的设定适合作为最小验证，却不能对应真实挖掘场景中持续多轮作业、作业区域不断变化、局部环境不断被改写的任务形态。与此同时，当前过于严苛的严格口径也容易把“模型已经学会完成任务”和“模型尚未达到高质量工业作业水平”混为一谈。现有文档已经明确指出，`strict_dump_complete` 仍然是 `0%`，但 `dump_complete_final_hold` 已经通过，因此后续最需要解释的是完成质量问题，而不是单纯的可学习性问题。

因此，V2 阶段要正面回答以下问题：

第一，底层技能是否可以从当前的单轮流程，升级为一个可重复调用、可作为连续作业基础单元的技能模块。

第二，系统是否能够在轻度变化的环境中仍然稳定执行，而不是只记忆固定场景和固定坐标。

第三，模型输出的动作是否能够保持自然、连续、相对平滑，而不是在技能切换处出现明显停顿、抖动和不自然重对齐。

第四，系统结构是否能够逐步演化为高层负责调度、低层负责执行的分层模式，为后续更长视距的连续挖掘任务打下基础。

---

## 三、V2 的总体目标

V2 阶段的总体目标可以概括为：

**在轻度变化环境中，训练一个可以稳定完成“挖土—转移—倾倒—归位”过程、能够被重复调用、动作相对平滑的底层挖掘技能，并为后续高层调度与连续多轮作业建立明确的接口与数据基础。**

这个总体目标与 V1 的区别非常明确。V1 的使命是证明单轮任务可学；V2 的使命，则是把“会做一次”推进到“可以反复做、在变化中做、连续地做”。文档中也已经给出了相同方向的推进建议，即将后续重点从“是否学会任务”转向“如何冻结 `v1` 业务基线、如何围绕严格口径做 failure analysis、以及是否将 `qvel` 等已经验证有效的变量迁移到下一阶段继续验证”。 

---

## 四、V2 的五个阶段及其具体含义

## 阶段一：明确任务边界、评价逻辑和系统分工

这一阶段的重点不是立刻训练新模型，而是先把 V2 要解决的问题定义清楚。只有问题定义清楚，后续数据采集、模型训练、实验分析和系统开发才有统一标准。这个阶段需要首先明确：V2 的底层技能不再是旧的“挖土—转移—倾倒”，而是扩展为“挖土—转移—倾倒—归位”。加入“归位”这一步，是因为后续连续多轮作业不能每轮都停在一个不规则且难以接续的姿态上；底层技能必须在结束时回到一个适合作为下一轮起点的相对规整状态。

同时，这一阶段还需要重构评价逻辑。V2 不应继续把“零抛洒”或近似“绝对无错误”的严格口径作为唯一主目标，而应把评价拆分为三个层面：一是任务是否完成，例如是否完成有效装载、有效转移、有效倾倒和归位；二是完成质量如何，例如抛洒量、残余桶内质量、碰撞情况和目标区外掉落情况；三是动作是否平滑，例如是否出现速度突变、明显停顿、切换僵硬等现象。现有文档已经说明，当前推荐主口径是 `dump_complete_final_hold`，而更严格的口径更适合用于 failure analysis，而不是唯一的成败判断。 

此外，这一阶段还需要提前明确高层与低层的分工边界。未来如果要引入高层调度器，那么高层应当负责决定“下一步去哪里挖、往哪里倒、完成后回到哪里”，而低层则负责在给定目标条件下稳定执行一次局部技能。只有边界明确，后续系统扩展才不会在职责上混乱。

这一阶段的预期目标，是形成一套清晰、统一、可执行的问题定义框架。换句话说，在阶段一结束时，团队内部应当对以下内容形成共识：V2 的最小技能单元是什么，V2 的主评价指标和诊断指标分别是什么，V2 关注的核心能力是什么，以及未来高低层系统准备如何分工。

---

## 阶段二：围绕新任务定义重组 V2 数据采集方案

在任务边界和评价逻辑明确之后，下一步必须重新设计与 V2 目标相匹配的数据采集方案。原因很简单，模型最终能学到什么，很大程度上受限于数据中记录了什么。V1 的数据更适合支撑单轮固定流程，而 V2 要学习的是“带归位的完整底层技能”“可在轻度变化环境中执行的技能”“未来可支持高层多次调用的技能”，因此仅靠旧数据并不能支撑 V2 的目标。

这一阶段的重点，是重新定义示教采集模板和数据结构。首先，新的 demo 不应在“倾倒完成”时就立刻结束，而应完整录到“归位完成”，从而让每条示教都对应一个完整的 V2 primitive。其次，需要在 metadata 中补充与 V2 有关的新字段，例如本轮目标条件、场景扰动参数、局部配置编号、操作员信息和数据录制上下文等。文档中已经强调，实验管理和训练 setup 的补充，不是为了让系统变复杂，而是为了在 baseline 表现不理想时，能准确区分问题更可能来自数据、任务逻辑、实验设置还是策略本身，因此 metadata 和实验记录能力是 V2 继续推进时必须继承并强化的基础。 

这一阶段还需要开始引入轻度随机化。这里的轻度随机化，不是一次性把全部场景因素都放开，而是有控制地让土堆位置、起始姿态、目标箱相对位置等因素发生有限范围变化。这样做的目的，是逐步打破模型对固定绝对坐标的依赖，迫使其开始利用视觉和相对状态信息做决策，而不是继续“背题”。

这一阶段的预期目标，是产出第一版服务于 V2 的正式数据集，并形成清晰的数据采集规范、目录约定和 metadata 方案。阶段二结束时，团队应当能够明确回答：V2 数据集录什么、录到哪里、在什么条件下结束、记录哪些额外信息，以及数据中的变化范围控制在什么程度。

---

## 阶段三：训练并验证 V2 的底层技能模型

在有了与 V2 目标匹配的数据之后，才进入真正意义上的底层技能训练阶段。这个阶段的重点，不是直接挑战“挖空一个区域”这样的长时程复杂任务，而是先验证：新的底层技能是否可学，是否能够在带有轻度变化的环境下稳定执行，是否具备作为后续连续作业基础单元的价值。

这一阶段训练的对象，应当是新的技能定义，也就是“挖土—转移—倾倒—归位”。这个技能比 V1 更长、更完整，因此必须单独验证其可学习性。此外，这一阶段还需要重点观察动作质量是否改善，尤其是你已经明确提出的“不要卡顿”这一目标。V2 不仅要求会完成任务，还要求动作在时间维度上连续、自然。现有文档已经指出，在既有对照实验中，`qvel` 对 dump phase 的控制稳定性有明确帮助，其引入使主口径成功率从 `30%` 提升到 `60%`，同时显著降低了碰撞次数和不安全距离计数，这意味着动态状态信息很可能与 V2 所关注的平滑控制高度相关。

因此，阶段三除了要训练和验证新的 V2 底层技能，还应开始系统评估：是否需要将 `qvel` 从过去的对照变量，升级为 V2 中的正式候选输入之一。更一般地说，这一阶段还需要开始建立动作平滑性的分析方法，例如统计速度突变、关节运动不连续、技能尾段到下一段过渡是否自然等。

这一阶段的预期目标，是证明 V2 的底层 primitive 不只是概念上合理，而是在实际训练和 rollout 中可学、可用、可作为后续多轮调度的执行基础。阶段三结束时，团队应当能够明确判断：新的技能定义是否成立，轻度随机化是否尚在模型能力范围内，动作平滑性是否比旧版更符合连续作业的要求，以及哪些输入变量对 V2 的目标最重要。

---

## 阶段四：引入目标条件并验证多轮连续调用能力

当新的底层技能已经基本稳定之后，项目才进入从“单轮技能”走向“连续作业原型”的过渡阶段。这个阶段的核心思想是：底层 skill 不应只是一个固定模板动作，而应逐渐演化为一个可以接收目标条件并在不同目标下执行的模块。未来真正的连续作业，并不是机械地一遍遍播放同一个动作序列，而是高层根据当前作业区状态不断给出下一轮局部目标，底层则围绕该目标完成一次具体技能。

因此，阶段四首先要做的是定义并引入目标条件表达，例如本轮应去挖掘的局部区域、本轮的目标倾倒区域、本轮完成后的归位位置等。然后需要验证，在不同目标条件下，底层技能是否仍然能够较为稳定地执行。更重要的是，这一阶段必须开始检查多轮连续调用时的衔接质量，也就是你最关心的动作卡顿问题。如果一轮 skill 结束后，下一轮 skill 需要明显停顿、重新找位、速度突变或姿态重对齐，那么系统虽然表面上可以执行多轮，但并不具备真实连续作业价值。

阶段四的高层调度器不一定要一开始就是学习式模型。完全可以先使用规则式、脚本式或启发式方法，为底层依次下发若干局部目标，从而验证系统是否已经具备连续执行原型的基本条件。这样做的好处是，可以在不引入额外学习复杂度的前提下，先把“高层给目标—低层执行—回传结果—进入下一轮”这条闭环跑通。

这一阶段的预期目标，是形成一个可以在有限规模下多轮连续运行的系统原型。阶段四结束时，团队应当能够回答：底层技能是否已经具备 goal-conditioned 的雏形，多轮调用时最主要的卡顿发生在哪里，归位设计是否足以支撑下一轮接续，以及高层与低层之间的交互是否已经形成清晰接口。

---

## 阶段五：逐步扩展到长视距连续作业任务

当底层技能已经稳定，目标条件表达已经明确，多轮连续调用机制也已经初步可行之后，项目才真正进入更复杂的长视距连续作业阶段。这一阶段对应的任务，不再是简单地重复若干个预先定义好的局部技能，而是根据当前作业区的实际变化，不断决定“下一铲应该去哪里”“当前区域是否已挖够”“下一步是否需要换方向或换区域”。

这意味着，阶段五真正引入的是动态环境中的高层规划问题。作业区域在每一轮技能完成后都会发生变化，因此高层不再只是按顺序给出固定目标，而需要根据当前状态不断重规划。低层则继续作为局部技能执行器，在高层给定目标后完成一次挖掘动作。这种分层结构，正是 V2 之所以前面要逐步铺垫任务定义、数据格式、目标条件和接口边界的原因。

阶段五的评估方式，也不再只是看单轮是否成功，而需要开始关注更长时间尺度上的累计完成量、持续运行的稳定性、动作连贯性、误差积累情况以及整体作业效率。只有到了这个阶段，项目才真正开始接近你最初提出的那类目标，即在动态变化的作业区域中不断重复挖掘动作，逐步完成更真实的连续作业任务。

这一阶段的预期目标，是把项目从“单轮演示型模仿学习系统”推进为“面向连续作业的分层智能系统”雏形。阶段五结束时，团队应当能够看到：系统已经不再只是会完成一次固定动作，而是能够在更长时程上连续工作，并逐步承担更接近真实工程需求的任务。
